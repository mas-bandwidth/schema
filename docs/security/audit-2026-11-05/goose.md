# Goose leg — guard audit, 2026-11-05 (card sca-goose.w6, report-only)

Scope audited at base `ee0568bb6476cedf07479b2f414ef49c28f27d66`: the Goose
packet generator (`internal/codegen/goose/**`), the Goose table generator
(`internal/codegen/goosetable/**`), the emitted runtimes they copy beside the
generated modules (`internal/codegen/goose/runtime/*.goose`,
`internal/codegen/goosetable/runtime/*.goose`), the generated modules and
goldens reachable from those generators, the hostile/fuzz entry points
(`test/goose-hostile/**`, `test/conformance/goose/**`, `make/goose.mk`,
`make/goose-fuzz.mk`, `internal/ci/hostilecorpus/corpus/**`), and the views,
message, fixed, JSON, block and cook surfaces the table generator emits. The
vendored `serialize*.goose` packet bitstream runtime is out of scope (own
card); the generated calls into it are audited here. Cooked and block forms
are the trusted class (build-version and integrity gated, `docs/SECURITY.md`);
their `open` entry points are included because they validate caller-supplied
buffers before dereferencing offsets.

Method (report-only ruling): code reading only. No reproductions, no new
hostile-input tests, no fuzz corpora, and no proof inputs were created. Every
finding names the reduction and the test or corpus row that *would* pin a fix;
none was created. No generator change was made, so every finding remains open.
Every row in the entry-point table and every finding cites `file:line` at base
`ee0568bb6476cedf07479b2f414ef49c28f27d66` so it is grep-verifiable. The Goose
compiler pin is a Linux binary (`make/goose.mk`: `goose-v2026.2-linux-x64`);
this audit ran on macOS (darwin/arm64) with no bench tooling present, so no
generated Goose program was compiled or run — see Gates.

Verdicts: **bounded** = the cited check refuses or clamps before the hostile
value can drive an out-of-bounds read/write, integer overflow, unchecked
allocation, uninitialized read, or unbounded recursion; **open** = a finding
below owns the row. Counts: 184 manifest cases in
`internal/ci/hostilecorpus/corpus/manifest.tsv` (168 `text`, 9 `wire`,
2 `message`, 1 `message_novocab`, 4 `announce*`); the table below covers every
distinct generated entry-point shape.

## Findings (all open; report-only — no fix attempted)

### F-G-01 — Generator quotes descriptor strings with Go `%q`, whose escapes are not Goose's
- Where: `internal/codegen/goosetable/goosetable.go:498`–`goosetable.go:500` (`name`, `slot`, `json`), `internal/codegen/goosetable/goosetable.go:666` (`def_s`, a string field's declared default bytes), `internal/codegen/goosetable/json_form.go:76` and `json_form.go:365` (variant/flags name lists), compared with the port's own correct quoter `stringLit` at `internal/codegen/goosetable/descriptors.go:88`–`descriptors.go:110`.
- What untrusted input can reach/do: schema-author text that is not an identifier — a `json = "…"` key (`goosetable.go:500`), a `string(N)` default's bytes (`goosetable.go:666`) — is rendered with Go's `strconv.Quote` rules (`%q`). Go emits `\a`, `\v`, `\f` and `\uXXXX` for bytes/runes Goose's string grammar (as `descriptors.go:88` itself records it: `\n \t \r \0 \\ \" \' \xNN`) does not list, so a schema carrying such a byte in a JSON key or a string default can generate a `.goose` module the pinned Goose compiler refuses, or reads back as different descriptor text. Identifiers (`goose.go:429`, `goose.go:452`, enum variant names) are ASCII-only at the scanner (`internal/scanner/scanner.go:298`) and are not affected. This is build-time only: generation fails closed or the descriptor text diverges; no generated reader is weakened.
- Severity: **low** (build-time schema-text fidelity; fail-closed at the Goose compile).
- Suggested reduction: route every non-identifier string the table surface emits (`fieldDesc` name/slot/json, `def_s`, the JSON name lists) through `stringLit` (`internal/codegen/goosetable/descriptors.go:88`) instead of `%q`.
- Pin that would fix it: a `goosetable` generator test whose schema carries a control byte (e.g. U+0007) in a `json = "…"` key and in a `string(N)` default, asserting the emitted descriptor text round-trips through the port's own string-literal rule. Named only — not created under report-only.

### F-G-02 — JSON duplicate-key and `required`-seen tracking uses a fixed 512-bit stack bitmask (`seen[8]`)
- Where: `internal/codegen/goosetable/runtime/schema_json.goose:1368`–`schema_json.goose:1371` and `schema_json.goose:1488`–`schema_json.goose:1491` (typed form), `internal/codegen/goosetable/runtime/json_value.goose:1433`, `json_value.goose:1485`–`json_value.goose:1488` and `json_value.goose:1904`–`json_value.goose:1907` (flat-value form).
- What untrusted input can reach/do: a JSON object for a table with more than 512 declared fields (or an enum-keyed array with more than 512 slots) where a field at index 512 or above is duplicated in the text, or marked `| required` and omitted. Every bitmask access is explicitly guarded (`index < 512`, `slot < 512`, `i < 512`), so no out-of-bounds access is possible; beyond index 511, duplicate-key counting and missing-required refusal are silently elided to keep the reader allocation-free — the same documented trade the C leg carries.
- Severity: **info** (explicitly bounded guards; memory-safe; verdict divergence only for tables past 512 fields).
- Suggested reduction: none required for current schemas; if tables past 512 fields ever require JSON duplicate or missing-required tracking above index 511, size the bitmask `(max_fields + 63) / 64` words per unit.
- Pin that would fix it: a generator test with more than 512 fields if that scale is targeted. Named only.

### F-G-03 — Shared hostile corpus: the Goose runner answers only the `wire` carrier (9 of 184 cases)
- Where: `test/goose-hostile/runner.goose:50`–`runner.goose:55` (any carrier other than `wire` prints `absent`), `internal/ci/hostilecorpus/corpus/manifest.tsv` (168 `text`, 2 `message`, 1 `message_novocab`, 4 `announce*`, 9 `wire` at base `ee0568bb6476cedf07479b2f414ef49c28f27d66`), and `make/goose-hostile.sh`, which counts absences and fails only when no case ran at all. `test/goose-hostile/known-findings.tsv` carries no rows.
- What it means: the Goose typed JSON readers (E21), flat-value JSON (E22), message announcement (E19) and message batch (E20) — all landed surfaces — are exercised by the Goose conformance drivers and Go-driven unit tests, but not by the shared corpus rows that pin the other ports' text/message/announcement verdicts to the Go engine's. A verdict divergence on those carriers (for example a `text` refusal reason) would not redden `schema-goose-runs-hostile-corpus`.
- Severity: **low** (corpus coverage shape; the surfaces have their own gates, and adding carriers is outside this report-only card).
- Suggested reduction: teach `test/goose-hostile/runner.goose` the `text`, `message` and `announce*` carriers through the generated typed/flat readers it already imports, in a future corpus card.
- Pin that would fix it: those carriers answering in `make/goose-hostile.sh` with zero absences for schemas the target carries. Named only.

### F-G-04 — Packet `Read<T>` leaves partially-written fields in the caller's value on refusal
- Where: `internal/codegen/goose/wire.go:139`–`wire.go:144` (the reader writes into `value` field by field and returns `false` at the first refusal, e.g. `internal/codegen/goose/read.go:87` lands bytes before the UTF-8 refusal at `read.go:91`), compared with the table forms, which discard the whole load (`internal/codegen/goosetable/runtime/wire_load.goose:1977`), and the typed JSON form, which resets the value on failure (`internal/codegen/goosetable/json_form.go:662`).
- What untrusted input can reach/do: a packet that passes its early fields and fails a later one leaves the caller's struct holding the early fields' hostile values (each individually range-checked) beside stale or default later fields. No out-of-bounds or unchecked value is reachable — every landed field passed its own refusal — and this is the packet idiom every target shares (SPEC's error-idiom table: `bool` early-out); the risk is only a caller that inspects the value after `false`.
- Severity: **info** (shared packet idiom; memory-safe; callers must discard on `false`, as the stream's latched reason already signals).
- Suggested reduction: none required; if the port ever wants the table forms' guarantee on packets, document "the value is unspecified after `false`" on the generated `Read<T>` comment (`internal/codegen/goose/wire.go:137`).
- Pin that would fix it: a doc-comment sentence, or a `Zero<T>`-first reader if the guarantee is ever chosen. Named only.

## Generator audit notes (no finding)

- **Identifier and path safety**: schema identifiers are ASCII-only at the scanner (`internal/scanner/scanner.go:298`–`scanner.go:302`); the package/namespace is refused when it is no Goose identifier, a Goose keyword, a scalar type, `std`, `main` or the runtime namespace `schema_rt` (`internal/codegen/goose/goose.go:171`–`goose.go:187`); a name declared twice in the unit namespace refuses by name (`goose.go:264`–`goose.go:270`); a schema file colliding with a runtime module, a `<Base>Table` module, a `<Base>Block`/`<Base>Cook` side module or a package module refuses by name, folding case (`goose.go:179`–`goose.go:185`, `internal/codegen/goosetable/goosetable.go:230`–`goosetable.go:256`, `internal/codegen/goosetable/accel.go:25`–`accel.go:36`). Output file names derive from `f.Base` (`internal/codegen/goose/goose.go:118`, `internal/codegen/goosetable/goosetable.go:191`); no shell command is constructed from schema text in either generator package.
- **Doc comments cannot inject code**: `ir.DocComment` re-prefixes every doc line with the comment marker (`ir/doctags.go:22`–`doctags.go:34`), and descriptor doc/tag text goes through the Goose-correct `stringLit` (`internal/codegen/goosetable/descriptors.go:88`) — F-G-01 is the remaining `%q` surface, not the doc path.
- **Write side refuses in every build**: packet writers check every value before the runtime sees it (`internal/codegen/goose/write.go:26`, `write.go:70`, `write.go:93`, `write.go:118`) because Goose has no build-removable assert; fixed writers refuse a broken contract before appending (`internal/codegen/goosetable/fixedform.go:1108`–`fixedform.go:1111`). Writes are the caller's responsibility per `docs/SECURITY.md`; read here only for partial-append behaviour, which is nil on refusal.
- **Allocation is input-bounded on every load path**: list/map storage reservations are capped by bytes remaining (`wire_load.goose:1052`, `wire_load.goose:1345`), node records cost at least two wire bytes each (`wire_load.goose:1660`–`wire_load.goose:1671`), and by-value recursion depth is fixed by the schema (a type cannot contain itself by value), while every input-driven recursion carries an explicit cap (JSON 128, message skip 128, retain 64).
- **Tolerant vs strict**: tolerant table/message/fixed reads clamp and count (clamped, widened, unknown, duplicate) and discard only on damage; strict reads name the first such event as their refusal (`wire_load.goose:123`–`wire_load.goose:135`, `fixedform.go:1161`–`fixedform.go:1169`). No tolerant path stores a value its strict sibling would call out of range without counting it.
