# Elixir reader audit

Report only. The serialize runtime was not audited. Findings are about the emitters in `internal/codegen/elixir/` and `internal/codegen/elixirtable/`, the readers those emitters copy into `generated/` and the goldens, and the bounds those readers rely on. No input was added.

## Findings

### `internal/codegen/elixirtable/messageform.go:474`

high. An announcement plus a form-2 batch reaches `zero_width_run`. The refusal there runs only when `shape.max` is `0xFFFFFFFF` and the count exceeds the bits still in the batch. Otherwise `List.duplicate` (`messageform.go:477`) builds the list before any further payload is required. `shape/1` for kind 14 (`messageform.go:1213`) accepts a min and a max up to `0xFFFFFFFF` inclusive, so every smaller max is a legal announcement, including a min equal to that max. `read_array` (`messageform.go:422`) reads `bit_length(shape.max - shape.min)` bits and adds them to min. `bit_length(0)` is 0 (`messageform.go:618`), so equal bounds put the announced min on the wire with no count field. For any other difference, the width `bit_length` returns can name a count above max minus min. `read_elements` (`messageform.go:450`) treats a value that returns the same cursor as zero-width: kind 0 and kind 32 (`messageform.go:370`), a packing-1 scalar whose width is 0 (`messageform.go:529`, and `get_bits` of 0 at `messageform.go:555`), or a nested run of those. The comment above the clause calls every smaller max a declared capacity. That max comes from the announcement, not from the local schema. `max_entries` (4096) limits how many vocabulary entries are installed, not the numeric max inside one entry. `load_messages` (`messageform.go:161`) catches a non-finite float and does not catch this allocation. An element that consumes bits returns `:malformed` when the batch runs out; that path is outside this finding. The exact `0xFFFFFFFF` path, held to the bits left, is the floor this reader already has. Reduction: apply the bits-left refusal to every zero-width run, and refuse a count above max minus min before allocating. An announced max below the sentinel is a wire claim. not added: report-only.

### `internal/codegen/elixirtable/messageform.go:771`

high. `open_file` bounds an announcement id-table count by the bytes the file can hold, then `unique_ids?` (`messageform.go:791`) scans the remainder for each id. `read_vocab` (`messageform.go:892`) and `parse_entries` (`messageform.go:997`) apply `max_bytes` 65536 and `max_entries` 4096 after that scan. `entries_here` (`messageform.go:712`) is the unit's own entry count and is not a cap on the announced table. The variable-form open refuses a count above 4096 before its distinctness check (`variableform.go:1522`). Reduction: refuse a count above 4096 before `unique_ids?`, the same predicate the variable-form open uses. not added: report-only.

### `internal/codegen/elixirtable/variableform.go:3426`

medium. `clamp_int` returns the storage integer unchanged unless the field map carries `min` and `max`. `read_payload` for `:int` (`variableform.go:2161`) and `clamp_list_int` (`variableform.go:3428`) both go through it. A bare `bits(N)` is emitted with a `:bits` key (`variableform.go:7942`) and with `min` and `max` only when `TableRawRange` returns ok (`variableform.go:7944`). `TableRawRange` (`ir/tablekind.go:299`) returns not-ok when `HasIntRange` is unset. The stored word is four bytes up to 32 bits and eight above (`variableform.go:7930`), so a magnitude above `2^N - 1` fits in the slack and is returned, and the clamped counter does not move. A strict load therefore accepts it. The JSON path already masks the same key (`int_domain_bounds`, `variableform.go:4761`). This is a domain miss. The integer does not overflow. Reduction: mask a `bits(N)` value to `(1 <<< bits) - 1` on the wire reader and count it clamped, as `int_domain_bounds` does. not added: report-only.

### `internal/codegen/elixirtable/fixedelixir.go:1057`

medium. `leafDec` returns the raw storage integer when `fixedRangeOf` answers `"nil"`. `fixedRangeOf` (`fixedplan.go:99`) returns nil when `HasIntRange` is unset, and `fixedWriterBoundsOf` (`fixedwriterbounds.go:55`) returns no row when `TableRawRange` is not-ok for the writer field. The slot width is `8 * TableFixedStorageBytes`, the rounded width, so the same slack past N is kept and not counted clamped. `<name>_fixed_load` reaches this through `<name>_fixed_decode`. A declared int range is still clamped. Reduction: mask `bits(N)` to `(1 <<< bits) - 1` on the projection, and on the writer-range pass when the lineage entry has no declared int range. not added: report-only.

### `internal/codegen/elixirtable/variableform.go:5348`

medium. `json_int_digits` accumulates an arbitrary-precision integer with no length limit, and `json_digits` (`variableform.go:5374`) accumulates a digit list the same way. `fixed_raw` (`variableform.go:5461`) says a 511-byte token cap bounds those digits. The only `511` in this file is that comment. A token that cap would refuse is built, then saturated by `clamp_json_int` (`variableform.go:4734`). An exponent shift above 700 or below -700 is still decided before `Integer.pow`. A node label stops at `2^64 - 1` (`variableform.go:5171`). Depth 128 (`variableform.go:5081`) is a real cap. Reduction: refuse a number token longer than 511 bytes before the digits accumulate, the cap `fixed_raw` already cites. not added: report-only.

### `internal/codegen/elixirtable/variableform.go:2260`

medium. `read_payload` for a by-value table calls `read_element` (`variableform.go:3072`) with no depth, and `read_list_elements` for kind 13 (`variableform.go:2875`) does the same. The message reader stops past 128 (`messageform.go:332`, `messageform.go:358`). JSON stops past 128 (`variableform.go:5081`). Retain stops past 64 (`variableform.go:7366`). A fixed layout stops past 64 (`fixedruntime.go:761`). `load`'s catch (`variableform.go:1466`) covers a missing required field, a count over the extent cap, a non-finite float, and wire damage. A stack error is not among them, so a nesting the walk cannot finish kills the process instead of returning malformed. A unit whose tables contain a table by value lets the wire choose that depth. Each level is several frames and a few bytes, so this is stack, not an allocation. A schema whose tables do not contain one another is bounded by that schema's own depth; the emitter still emits the uncapped walk. Reduction: thread a depth and refuse past 128, the cap the message reader uses for the same family of wire walks. Retain and the fixed layout use 64 for a different walk. not added: report-only.

### `internal/codegen/elixirtable/messageform.go:413`

low. `read_string` takes `bit_length(shape.max)` bits and copies that many bytes. It does not refuse a count above `shape.max`. Where max is not one less than a power of two, that width admits a larger count. `take_bytes` still stops at the bits the batch has left, and the string shape accepts an announced max only through `0x7FFFFFFF` (`messageform.go:1201`). The packet reader refuses a count above its declared bound before the copy. Reduction: refuse `n > shape.max` before `take_bytes`. not added: report-only.
