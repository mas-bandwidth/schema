### F-C-01 — Variable-root `<root>_load_retain` does not allocate `nodes.blob_named`, leaving `report->blob_shared` at zero
- Where: `internal/codegen/ctable/retain_graph.go:61`–`retain_graph.go:66` (`emitRetainFileRoot`), compared with `internal/codegen/ctable/graph.go:957`–`graph.go:978` (`emitGraphLoad`), `internal/codegen/ctable/graph.go:370` (`table_node_resolve`), and `internal/codegen/ctable/graph.go:380`–`graph.go:385` (`table_node_blob_mark`).
- What untrusted input can reach/do: a variable-form wire file in which two `*bytes` or `*string` pointer slots reference the same blob directory record (`docs/SPEC-TABLES.md` §2.5), handed to `<root>_load_retain`. While `<root>_load_tolerant` (`internal/codegen/ctable/graph.go:957`–`graph.go:978`) allocates `nodes.blob_named` (`(uint8_t *)table_allocate(table_default_allocator(), (int64_t)records+1)`) whenever `len(ir.BlobPointerFields(g.unit)) > 0`, `<root>_load_retain` (`internal/codegen/ctable/retain_graph.go:61`–`retain_graph.go:66`) leaves `nodes.blob_named == NULL` on both the `total < 0` fallback path and the main region path. Both `table_node_resolve` (`graph.go:370`) and `table_node_blob_mark` (`graph.go:382`) check `nodes->blob_named != NULL` before indexing, so no null dereference is reachable, but `table_node_blob_mark` returns early and `report->blob_shared` stays `0` instead of counting the shared blob naming as `<root>_load_tolerant` and the Go oracle do.
- Severity: **low** (report-ledger divergence on `<root>_load_retain`; memory-safe).
- Suggested reduction: emit the same `len(ir.BlobPointerFields(g.unit)) > 0` allocation and `table_release` of `nodes.blob_named` in `emitRetainFileRoot` (`internal/codegen/ctable/retain_graph.go:61`–`retain_graph.go:66`) as in `emitGraphLoad` (`internal/codegen/ctable/graph.go:957`–`graph.go:978`).
- Pin that would fix it: a `ctable` test on `tables/blobs` passing a shared-blob wire payload to `blobdemo_pack_load_retain` and asserting `report.blob_shared == 1`. Named only — not created under report-only.

### F-C-02 — Oversized blob refusal (`SCHEMA_TABLE_REFUSE_BLOB_OVER_SIZE_CAP`) in `load_graph` is overwritten as `malformed` / `SCHEMA_TABLE_REFUSE_WIRE_DAMAGED`
- Where: `internal/codegen/ctable/graph.go:920`, `internal/codegen/ctable/graph.go:971`, `internal/codegen/ctable/graph.go:990`, and `internal/codegen/ctable/cook.go:124`–`cook.go:138` (`table_report_strict_refuses`).
- What untrusted input can reach/do: a variable-root wire payload containing a blob record (`*bytes` or `*string`) whose declared span exceeds `UINT32_MAX` (`docs/SPEC-TABLES.md` §2.5). At `internal/codegen/ctable/graph.go:920`, `load_graph` sets `reader->report->reason = SCHEMA_TABLE_REFUSE_BLOB_OVER_SIZE_CAP` and returns `0` without setting `reader->report->refused = 1` or `nodes->refused = 1`. In `<root>_load_tolerant` (`graph.go:970`–`graph.go:971`), `load_layout` returns `-1` (`total < 0`), the fallback path runs `load_graph`, sees `nodes.refused == 0`, and executes `report->malformed = 1; return NULL;` without setting `report->refused = 1`. In `<root>_load_builder_tolerant` (`graph.go:990`), `nodes.refused` only propagates `SCHEMA_TABLE_REFUSE_COUNT_OVER_EXTENT_CAP`. Furthermore, `table_report_strict_refuses` (`internal/codegen/ctable/cook.go:127`–`cook.go:132`) only preserves `SCHEMA_TABLE_NON_FINITE_FLOAT` and `SCHEMA_TABLE_REFUSE_COUNT_OVER_EXTENT_CAP` when `report->refused` is set, collapsing any other `report->refused` reason to `SCHEMA_TABLE_REFUSE_UNKNOWN_FORM` and any `!decoded || report->malformed` to `SCHEMA_TABLE_REFUSE_WIRE_DAMAGED`. The load fails closed before allocating or copying the oversized blob, but the reported refusal reason does not name `SCHEMA_TABLE_REFUSE_BLOB_OVER_SIZE_CAP`.
- Severity: **low** (fail-closed before allocation; misreports refusal reason on `> 4 GiB` blob records).
- Suggested reduction: set `reader->report->refused = 1; nodes->refused = 1;` at `internal/codegen/ctable/graph.go:920`, propagate `report->reason` when `nodes.refused` is set in `graph.go:971` and `graph.go:990`, and add a `SCHEMA_TABLE_REFUSE_BLOB_OVER_SIZE_CAP` branch in `table_report_strict_refuses` (`internal/codegen/ctable/cook.go:128`).
- Pin that would fix it: a `ctable` unit test verifying `report.refused == 1`, `report.reason == SCHEMA_TABLE_REFUSE_BLOB_OVER_SIZE_CAP`, and `report.refuse_reason == SCHEMA_TABLE_REFUSE_BLOB_OVER_SIZE_CAP` when `load_graph` rejects a blob record with `body.size > UINT32_MAX`. Named only.

- Pin that would fix it: a `ctable` unit test mirroring `internal/codegen/gotable/jsonbase64escape_test.go` over fixed `bytes(N)` and variable `*bytes` fields. Named only.

### F-C-04 — `<root>_load_measure_ex` does not initialize `*reason` at entry
