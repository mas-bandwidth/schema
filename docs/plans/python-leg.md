# A Python leg: the layers, bottom up

The owner, 2026-11-03: *"I would also like to extend to support python too."*

This page sets out the layers of a new Python target, from the bottom up. Each
layer has what it guarantees, how that is checked, and what it depends on. It
also lists the decisions that need the owner before anything is built. The house
rule is that the layers of a new system are settled with the owner before building,
and each one is secured before anything above it starts. So this page is for
correcting first, and building second. The roadmap work-set is `port/python`
in `docs/roadmap.sexp`, one task per layer.

The leg is modeled on how goose and moo came to `main`:

- goose: `0c0a9204b` brought the skeleton, then the packet wire over
  `serialize.goose` (#2281), then the table wire (#2275), the conformance
  control, the fixed lineage and the readiness entry.
- moo: docs/PORT-MOO.md, THE LAYERS 1 to 7.

It joins the registries the way docs/CONTRIBUTING.md "Adding a language"
describes: one file or one directory per language, discovered rather than
listed, and only the three tolerated shared edits.

It is built to the contract on `strict-only-spec` (spec PR #2790) from
the first line:

- **One read.** Every read returns the whole value or refuses with no partial
  value.
- **The verdict is the cross-language contract.** A value is shown equal by
  writing it back byte-identical; reasons, counters and sizes are Python's own
  diagnostics.
- **Writes are deterministic.** The binary and JSON writers follow
  `deterministic-write` and `deterministic-json`.

Python never has a tolerant read, so it has nothing to cut later.

## What is on main today, and what happens to it

`python/packet.py`, `test/py-packet/f11` and the `tables-py-packet` gate with
its negative control (#1400, card s17pyw-f11, 2026-10-14) are a single
fixed-form row (F11 `plan_too_large`), written by hand. They break three house
rules:

- they run the runner's system `python3`, not a pinned interpreter;
- they carry the `malformed` flag, which the cut retires;
- they are not generated by the compiler.

They are scaffolding. Layer 0 removes them (the code, the Makefile block, the
`python/` row in AGENTS.md and the ci-full step), and the real leg replaces
them from layer 1 up. F11's rule returns in layer 5 as part of the fixed form.

**Models.** The leg implements state machines the house has already modeled
(framing, read order, card versioning). It adds none of its own, so it needs
no new TLA+ module. The exception would be serialize.py hand-rolling a fixed
word buffer with a flush (index arithmetic over a reused scratch). In that
case P2 carries a layout model with a reversed witness, as the layout rule
requires. A Python `int` accumulator with no fixed width needs none.

**Tests.** `pyrun` runs the pinned interpreter in `t.TempDir()`: inputs go in
as files, answers come out on stdout as hex lines, with no real time, no
sockets and no network, and every test calls `t.Parallel()`. Anything timed
(the bench, a soak) is a functional test.

**Order.** P0 → P1 → P2 → P3 → P4 → P5 can all proceed before the cut lands,
once the cut's spec layer is ruled (P5 is built to its text). P6 and
everything above it wait for `strict-only/engine` and `strict-only/harness`.
Python then joins the cut's leg order as the sixteenth leg, with nothing to
delete.

## Decisions for the owner

**D1. Pure Python, or a compiled accelerator.** The house rule is the fastest
correct implementation in each language.

- (a) Pure Python, stdlib only: generated per-type code over serialize.py.
  Runs on CPython and PyPy, needs one implementation, and has no build step for
  users.
- (b) (a), plus the same source compiled with mypyc into a C extension as an
  optional speedup. One source, but a pinned mypy and a C compiler, and a
  wheel per platform.
- (c) A C extension: hand-written, generated, or the C leg's codecs reached
  through cffi. Fastest, but it is a second implementation in C that has to
  agree with the first, and it needs per-platform wheels and a compiler
  for users. ctypes call overhead per field would cancel most of the win.
- (d) Cython. The same trade-offs as (c), plus a second language in the tree.

**Recommendation: (a), with (b) as a named follow-on that ships only if it
measures a real win.** In Python the language's own floor is CPython executing
Python. A C extension is a C leg wearing a Python interface. Within (a),
fastest means measured: in P4, emit two shapes for one type (straight-line
generated code with locals bound, and a descriptor walk as Lua uses) and keep
the faster. Expect pure Python to be one to two orders of magnitude slower than
the C leg; the bench will say exactly how much.

**D2. Minimum Python version.**

- 3.10 reached end of life in October 2026.
- 3.11 is the oldest release still supported. It brought the faster CPython
  interpreter and zero-cost `try`, which matters if a refusal is an exception.
- 3.12 adds PEP 695 type syntax.
- 3.13 adds the free-threaded build, still experimental.

**Recommendation: 3.11 as the floor.** The generated code and runtime use
nothing newer. The toolchain pins two interpreters: the floor (newest 3.11.x)
and the newest stable CPython at pin time (confirm the release before
pinning). The leg runs on both, as the Lua leg's version differential does.

**D3. The toolchain pin.**

- (a) The python.org source tarball, by sha256, `./configure && make -j` into
  `dist/`, cached in CI by the pin. This is the Lua and Squirrel precedent.
- (b) python-build-standalone release archives, one sha256 per OS. Fast, and
  the Luau and Lobster precedent, but a third party's build.
- (c) The runner's or system `python3`. This is what the F11 seed does, and the
  house rule refuses it.

**Recommendation: (a).** Build from pinned source. The core modules the leg
needs (`struct`, `sys`, `os`) need no optional system libraries, so the build
is self-contained on macOS and Linux, and both interpreters build in parallel.
The analyzer (mypy in strict mode, or pyright, which brings Node) is installed
into the pinned interpreter with `pip --require-hashes` from a lock in the
tree. mypy is recommended because it adds no second runtime and is also what
D1(b) would use.

**D4. A serialize-family sibling, serialize.py.** Every one of the fifteen
legs stands on its own `serialize.<lang>`:

- each repository is listed in serialize's COMPATIBILITY.md at format 2.0;
- ci-full.yml pins the C++, C, C#, Go, Rust and JS ones by tag;
- the newer legs vendor theirs by sha256.

Options:

- (a) A new public repository, `mas-bandwidth/serialize.py`, ported against
  the family corpus and released before schema uses it.
- (b) No sibling: the schema runtime carries its own bit reader and writer.

**Recommendation: (a).** It is the family pattern. It also secures the bit
layer under its own outside judge (the family corpus) before schema is built
on top, and the bit layer is useful to Python users without schema. Creating
the public repository is your call.

**D5. Packaging.**

- (a) Generated code is emitted with the runtime beside it in the output
  package (a `_schema` subpackage, relative imports, serialize.py vendored
  inside), as every other leg emits its runtime. Nothing to install.
- (b) A PyPI package that generated code imports.
- (c) Both.

**Recommendation: (a) for the leg.** Publishing serialize.py (and any runtime)
to PyPI is a later decision, and yours: the PyPI account and its tokens are
yours, and never delegated to me.

**D6. Errors and the strict read.**

- (a) `T.load(data) -> T` raises `schema.Refused` (a `ValueError` subclass)
  carrying `.reason`, a diagnostic string that is never compared across
  languages. On success, an optional `report=` argument receives `unknown`,
  `widened`, `retained` and `retain_lost`. Writers raise `schema.InvalidValue`
  (a `ValueError` subclass) for an out-of-contract value. A refusal carries no
  value and does not touch the caller's objects.
- (b) Return a `(value, error)` pair.
- (c) Return `None` and fill a report.

**Recommendation: (a).** Exceptions are the Python idiom, they are zero-cost
on success from 3.11, and the shape leaves no place for a partial value.

The value model that goes with it:

- generated classes with `__slots__`;
- `int` everywhere, with range checks on write (128-bit is native);
- `float` with float32 fields packed through `struct` and checked;
- enums as `int` constants on a class with name tables, not `IntEnum`, which is
  slow to construct and cannot hold an unknown variant;
- `str` for text, encoded strictly so a lone surrogate refuses;
- `bytes` on read, and `bytes`, `bytearray` or `memoryview` accepted on write.

**D7. The JSON reader.**

- (a) Port the engine's reader.
- (b) Use the stdlib `json` module with hooks. Its dialect differs from the
  spec's: it accepts `NaN` and `Infinity`, keeps the last of duplicate keys,
  and decodes lone-surrogate escapes. Hooks can catch the first two but not
  the third.

**Recommendation: (a).** The JSON writer is the deterministic-JSON algorithm
in any case. Python's own float `repr` should be checked against it, not
assumed to match it.

**D8. Python and the v3.0.0 gate.** On 2026-10-28 you ruled that every port is
on main at parity before v3.0.0.

- (a) Python joins that gate, so 3.0.0 waits for P16.
- (b) Python is a post-3.0.0 port, held to the same bar but not blocking the
  release.

**Recommendation: (b).** The other legs are mostly acceptance work away from
100%, and Python is the full stack.
