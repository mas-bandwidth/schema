# THE THREE WAYS AN ELIXIR CASE ENDS (test/conformance/elixir/driver_impl.ex,
# each_case/3 and codec/2), held by make's elixir-case-outcomes gate beside
# expected.txt. The rows are in the DERIVED manifest's shape the driver reads
# (testdata/conformance/tables/FORMAT.md): an `instance` line keeps its
# markers, and a write-refusal line carries no verdict.
#
#   a codec ABSENT for the case (no unit module, or no such root in its
#     descriptors): an EMPTY <case>.absent;
#   a REFUSAL of a present codec: that surface's refusal answer, which on the
#     wire surface is <case>.absent HOLDING THE READ'S REASON (review F-174:
#     the shapes loaders refuse octets below their minimum, and an empty
#     .absent spelled that refusal as a missing codec);
#   a DRIVER ERROR (here a wire file that does not exist, a path naming no
#     field): no answer, the case named on stderr, the cases after it still
#     answered, and the surface's exit status non-zero.
#
# Every refused row sits beside a legal control on the same root, and every
# out-of-width token (an ordinal or a tag of 256 or 2^32 against a one-byte
# enum or union tag) beside an in-range one: the driver hands the BEAM integer
# through unnarrowed, and the codec, not the driver, refuses it.
