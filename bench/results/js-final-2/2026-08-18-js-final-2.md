## The headline: every correct JavaScript, one blend, C++ = 100

Blended geomean of per-row **time** ratios vs C++ (`100 × cpp_rate /
impl_rate`, best-of per §2.2), over the 22 rows comparable across all four
implementations: the 11 generated benches present in every column
(real_packet included), write and read. Lower = faster. ship_shallow and
message_batch are runtime-tier-only by construction (object views; a
continuous multi-message bitstream) and ride outside the blend; the
serialize.js hand-port is hand-written runtime code, so its blend rides on
the 8-row rt family against the same hand-written C++ runtime benches —
a like-for-like basis, footnoted, not the gen basis.

| implementation | blend (time, C++ = 100) | basis |
|---|---:|---|
| **C++** (generated + serialize v1.10.0) | **100.0** | 22 gen rows |
| **C** (generated + serialize.c v1.4.0) | **102.4** | 22 gen rows |
| **JS flat (SHIPS — codec=flat, zero-dependency generated)** | **1684.2** | 22 gen rows |
| **serialize.js hand-port v1.1.0 (compat/reference tier)** | *3427.3* | 8 rt rows vs C++ rt |
| **JS generated runtime-call (the old shape, for the record)** | **7662.3** | 22 gen rows |

The flat tier is **4.55x** the runtime-call tier blended, and the fastest
correct JavaScript on every one of the 22 rows. C/C++ parity holds again
(102.4 on this basis; 99.4 on sixlang's — the delta is basis, not drift:
this blend includes real_packet, where C leads, and excludes message_batch,
where C leads by more).

| implementation | write M msg/s | write (time, C++=100) | read M msg/s | read (time, C++=100) |
|---|---:|---:|---:|---:|
| C++ | 21.15 | 100.0 | 26.71 | 100.0 |
| C | 25.62 | **82.6** | 30.16 | **88.6** |
| JS flat | 1.45 | 1462.7 | **6.05** | **441.6** |
| JS runtime-call | 0.52 | 4076.7 | 0.61 | 4372.1 |

The flat read lands at **4.4x C++ time — inside Glenn's 4–8x band** — and
**9.9x faster** than the runtime-call shape it replaces. The write side is
vary-bound (§2.7's per-iteration field mutation, BigInt lanes on the 64-bit
fields — the probe measured flat ≈ wasm parity there): 14.6x C++, 2.8x the
runtime-call shape. Three independent measurements of the runtime-call
shape now agree (0.51/0.61, 0.51/0.61, 0.52/0.61).
