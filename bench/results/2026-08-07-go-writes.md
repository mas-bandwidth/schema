# 2026-08-07 — the Go write program: first profile, runtime fusion, both emitter levers

The gap ledger named the Go write column "the honest frontier, with no profile
on record" (490% of C++ at v4, the widest cell on the board). This pass
profiled it, convicted the cause, fixed the runtime shape it convicted, and
adopted the two C++-proven emitter levers in the Go backend. Two PRs, merged:

| repo | PR | branch | merged |
|---|---|---|---|
| serialize.go | #19 — write path: fuse the bounds check and bit packing into every per-field write | `optimize-write` | `7a7d89d` |
| schema | #13 — Go emitter: generation-time folded bit counts + bulk bytes for aligned [N]uint8 | `go-writes` | (this branch) |

## Banked predictions (written before the profile ran)

P1: the write twin of the read fix's inline-budget class — outlined write
wrappers carry the plurality of samples; fixing them is the biggest lever
(490% → low-300s). P2: folding bit counts worth +5–15% on ranged-int rows,
by C++ #8 analogy. P3: bulk-bytes worth testdata write +10–30%, read
+20–40% (C++'s read +70–80% would not fully transfer). P6: the macOS pprof
kevent artifact (PR #17) may force a fallback.

## The profile (M2, pprof over the corpus write loops, golden-gated)

Clean — **P6 refuted**: no kevent mis-attribution on go1.26.5/M2; PR #17's
caveat did not reproduce. Top of the write profile (11.60s samples):

```
3.21s 27.7% flat  (*BitWriter).writeBits (inline)
2.75s 23.7% flat  (*WriteStream).writeBits        4.45s 38.4% cum
1.45s 12.5% flat  (*WriteStream).SerializeInt     3.35s 28.9% cum
0.44s  3.8% flat  (*WriteStream).SerializeUint64  1.10s  9.5% cum
```

Line-level: inside `(*WriteStream).writeBits`, 660ms sat on the function
entry line and 790ms on `return nil` — pure call-boundary overhead — plus
970ms on the error-latch load and bounds check. `go build -gcflags='-m -m'`
gave the verdicts: `cannot inline (*WriteStream).writeBits: cost 107 exceeds
budget 80` (the read fix's 83-vs-80 class), `SerializeInt: cost 133`,
`SerializeInt64: cost 319`. So every bare field paid one outlined call that
round-tripped six fields of writer state through memory, and every RANGED
field paid two (SerializeInt outlined, calling writeBits outlined) — where
the post-#17 read path pays one fused call.

**P1 confirmed, with a refinement**: reads also pay one outlined call per
field — the write disease was the heavier per-call body and the ranged
double boundary, not outlining per se.

## The runtime fix (serialize.go#19) — the read fix's discipline, write side

- Writer state as **four flat fields** on the stream (`data`, `scratch`,
  `numBits`, `bitsWritten`). Pending bits = `bitsWritten&63` (every spill
  removes exactly 64, so they never drift); qword store offset =
  `(bitsWritten>>3)&^7`. Flat is load-bearing: the same body through
  `s.writer.X` selectors costs 84–93 against the budget of 80.
- **`tryWriteBits` fuses bounds check + packing at cost 64** — the exact
  cost `readBits` landed at in #17. Every per-field method is one outlined
  call with no calls inside; `SerializeInt`/`SerializeInt64` lose their
  second boundary.
- **`fail` poisons `numBits`** after latching, so the bounds check subsumes
  the per-call error load; writes after a latched error return the latched
  error and write nothing, exactly as before.
- Wire bit-for-bit identical (same values, widths, qword store sequence) —
  gated by the cross-language round trip and the schema wire goldens.

## The emitter levers (schema#13)

- **Generation-time folded bit counts** (C++ #8's mechanism, write side
  only): offset-from-min in a literal bit count through
  `SerializeBits`/`SerializeBits64`, range refusal supplied inline, the
  signed subtraction wrapping to the unsigned offset by Go's defined
  overflow. Scope = C++ #8's exactly: ranged int32/int64, counts, string
  lengths, enums, message/object tags, view quantized components and
  projected floats. Reads stay on runtime calls.
- **Bulk-bytes** for `ir.AlignedFixedByteArrays`-proven `[N]uint8` (C++ #7,
  the analysis placed in `internal/ir` for exactly this reuse):
  `SerializeBytes` both paths, per-byte loop everywhere unproven. One corpus
  site (TestData.FixedBytes[17]), as in C++. Wire goldens byte-identical —
  `git diff -- testdata/wire/` empty, all four language tests green.

## Prediction vs outcome

- **P1 CONFIRMED** (with the refinement above). Column magnitude: see the
  relative table below against same-run C++.
- **P2 REFUTED IN SHAPE, exceeded where it applies**: folding in Go is worth
  far more than the predicted +5–15% on ranged-heavy rows (1.35–1.37x
  emitter-alone) because it deletes an outlined call boundary per ranged
  field, not just the BitsRequired math — the CLAUDE.md rule holds
  ("re-convict per language"): C++ +14.7%, C# ~1.0x, Go up to 1.37x, all
  the same lever. But probebits moved only 1.04x — its fields are raw
  `bits()`/uint64, not ranged; the C++ probebits analogy did not transfer.
- **P3 CONFIRMED**: testdata write 1.30x (top of range, includes fold),
  read 1.31x (inside the predicted +20–40%).
- **P6 REFUTED**: the macOS profile was clean.

## The four-language sweep at the composed mains

One `bench/run.sh` invocation at schema `go-writes` + serialize.go main
`7a7d89d` (all four runners, golden gate held): CSV
`2026-08-07-go-writes-after-arm64-m2.csv`. Time relative to same-run C++
(C++ = 100%, medians over the 11 corpus benches; batch separately):

| backend | write | read | batch write | batch read |
|---|---:|---:|---:|---:|
| C++ | 100% | 100% | 100% | 100% |
| Rust | 186% (v4 188%) | 235% (v4 236%) | 106% (v4 110%) | 152% (v4 156%) |
| C# | 372% (v4 379%) | 343% (v4 343%) | 145% (v4 155%) | 196% (v4 204%) |
| Go | **323%** (v4 490%) | 384% (v4 387%) | **198%** (v4 236%) | 199% (v4 208%) |

**The Go write column closes 490% → 323%** — the banked "low-300s"
magnitude for P1, confirmed — and Go's write column now leads C#'s (372%).
Batch write 236% → 198%. The C++ denominator held: every C++ write row is
0.95–1.01x its v4 value, so the movement is all Go (go writes 1.04–1.83x
v4, reads within noise except testdata's intended bulk-bytes gain). The
other three languages ride along untouched (their runtimes and generated
code are at the v4 pins); their cells move only by C++/host drift.

What remains of the Go write gap is no longer unattributed wrapper
overhead: the per-field write is one fused call at the inliner's budget
edge, the same shape as the post-#17 read path — and the read column
(384%) shares it. The next honest frontier for both columns is the
one-outlined-call-per-field floor itself (zero-call needs the fast path
under ~50 of the 80 budget — not reachable with the spill in-body; priced
during this pass) and the tiny-message constant-folding class C++ enjoys
(test 696%, probe_header 1245% — the same rows Rust floors on, per the
ledger).
